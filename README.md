# Дипломный проект: автоматизация развёртывания приложения и инфраструктуры


## 1. О проекте

Цель дипломного проекта — построить облачную инфраструктуру и реализовать автоматизированный процесс развёртывания приложения с использованием подходов Infrastructure as Code, контейнеризации, оркестрации, CI/CD и мониторинга.

В рамках проекта создан Kubernetes-стенд в Yandex Cloud, подготовлены серверы, развёрнут кластер из трёх узлов, выполнена контейнеризация веб-приложения, настроена автоматизированная доставка новой версии приложения и организован мониторинг его работоспособности.

**Основные результаты проекта:**

- облачная инфраструктура описана с помощью Terraform;
- подготовка серверов автоматизирована с помощью Ansible;
- развёрнут Kubernetes-кластер из одного Control Plane и двух Worker-узлов;
- настроена сетевая связность Pod с использованием Flannel;
- приложение контейнеризировано с помощью Docker;
- образы приложения публикуются в Yandex Container Registry;
- настроен CI/CD pipeline на GitHub Actions;
- развёрнуто приложение с двумя репликами в Kubernetes;
- настроен мониторинг инфраструктуры и приложения с использованием Prometheus, Grafana и Blackbox Exporter.

## 2. Архитектура решения

Инфраструктура размещена в Yandex Cloud и состоит из трёх виртуальных машин, расположенных в разных зонах доступности.

| Узел          | Роль                            | Зона доступности |
| Control Plane | Управление Kubernetes-кластером | ru-central1-a    |
| Worker B      | Выполнение рабочих нагрузок     | ru-central1-b    |
| Worker D      | Выполнение рабочих нагрузок     | ru-central1-d    |

Для управления кластером используется kubeadm, контейнерная среда — containerd, сетевой плагин — Flannel.

Приложение развёрнуто в Kubernetes в двух экземплярах. Для доступа к нему внутри кластера используется Service, внешний доступ организован через NodePort.

Мониторинг построен на Prometheus и Grafana. Blackbox Exporter выполняет HTTP-проверки приложения, а Node Exporter предоставляет метрики операционных систем узлов.

## 6. Автоматизация доставки приложения — CI/CD

Для автоматизации процесса сборки и развёртывания приложения использовался GitHub Actions.

Настроенный pipeline обеспечивает последовательное выполнение основных этапов доставки:
1. Получение исходного кода из GitHub.
2. Сборка Docker-образа.
3. Публикация образа в Yandex Container Registry.
4. Обновление приложения в Kubernetes.
5. Проверка результата развёртывания.

Таким образом, процесс доставки новой версии приложения выполняется автоматически, без необходимости вручную собирать образ и выполнять обновление приложения на узлах кластера.

### Проверка доступности приложения

Для контроля доступности веб-приложения использовался Blackbox Exporter.

В отличие от сбора внутренних метрик приложения, Blackbox Exporter выполняет HTTP-проверку: отправляет запрос на адрес Kubernetes Service и анализирует полученный ответ.

В Prometheus собираются следующие показатели:

- `probe_success` — результат проверки доступности;
- `probe_http_status_code` — HTTP-код ответа;
- `probe_duration_seconds` — время выполнения проверки.

На основе этих метрик в Grafana настроены панели доступности приложения, времени ответа и HTTP-статуса.

В результате выполнения дипломного проекта создан и проверен облачный стенд, объединяющий инфраструктуру, контейнеризацию, оркестрацию, автоматизацию доставки и мониторинг.

| Направление              | Результат                                                 |
| Infrastructure as Code   | Создание и управление инфраструктурой с помощью Terraform |
| Configuration Management | Автоматизация подготовки серверов с помощью Ansible       |
| Containerization         | Сборка Docker-образа приложения                           |
| Container Registry       | Публикация образов в Yandex Container Registry            |
| Orchestration            | Kubernetes-кластер из трёх узлов                          |
| Networking               | Сетевое взаимодействие Pod через Flannel                  |
| CI/CD                    | Автоматизированная сборка, публикация и развёртывание приложения |
| Monitoring               | Сбор метрик Prometheus и визуализация в Grafana           |
| Application Availability | HTTP-проверки приложения через Blackbox Exporter          |

### Ограничения текущей реализации

На текущем этапе сохраняются следующие ограничения:

- Prometheus использует временное хранилище `emptyDir`; срок хранения метрик настроен на 24 часа;
- Grafana работает без постоянного хранилища, поэтому настройки и данные могут быть потеряны при пересоздании Pod;
- приложение проверяется по HTTP через Blackbox Exporter; собственный `/metrics` endpoint приложения не реализован;
- долговременное хранение метрик и отказоустойчивость мониторинга не настраивались.

Эти ограничения учитываются при оценке текущей реализации и могут стать направлениями дальнейшего развития проекта.
